## สกัดจากภาพ

ภาพเปรียบความรู้เป็นภูมิประเทศ มีบริเวณที่เชื่อมแน่น บริเวณที่กระจัดกระจาย ทางเชื่อมแคบ และพื้นที่ที่เข้าถึงยาก พร้อมแยกสามระดับ:

1. **Represented knowledge:** มีตัวแทนของข้อมูลบางอย่างอยู่ภายใน
2. **Accessible knowledge:** วิธีถามหรือการคำนวณเข้าถึงข้อมูลนั้นได้
3. **Stable knowledge:** เข้าถึงได้สม่ำเสมอจากคำถามหรือบริบทหลายแบบ

ปัจจัยในภาพคือความหนาแน่นของ representation, การเชื่อมต่อ, curvature และ accessibility ภาพยังเสนอให้ช่วยโมเดลด้วยการอธิบายคำศัพท์ เพิ่มบริบท และถามขั้นกลาง

## สถานะของกรอบอธิบายนี้

พบศัพท์และข้อเสนอใกล้เคียงในโครงการ HRIS แต่ยังระบุแหล่งเผยแพร่ต้นทางของภาพนี้โดยตรงไม่ได้ จึงควรใช้คำว่า basin หรือ semantic dark matter เป็นอุปมา ยังไม่ใช่ taxonomy ที่พิสูจน์ด้วยการวัดตามภาพ [HRIS Research](https://hrisresearch.org/)

โดยเฉพาะข้อความในภาพที่สรุปว่าการถามดีขึ้นคือพบเส้นทางเดิม และโมเดลไม่ได้เรียนสิ่งใหม่ เป็นเพียงคำอธิบายหนึ่งที่ต้องแยกจากทางเลือกอื่น: prompt อาจให้ข้อเท็จจริงใหม่ สอนวิธีทำ เพิ่มคำใบ้เฉลย หรือเปลี่ยนรูปแบบที่คุ้นเคย

## ความรู้เสริมที่ตรวจจากงานทดลองได้

งาน Eliciting Latent Knowledge from Quirky Language Models ฝึกโมเดลให้ตอบผิดอย่างเป็นระบบในบริบทที่กำหนด แล้วใช้ linear probes อ่าน activation พบว่าบางกรณีดึงคำตอบที่ถูกได้แม้ output จะผิด นี่เป็นหลักฐานใน setting ควบคุมว่าข้อมูลใน representation กับคำตอบปลายทางอาจต่างกัน [paper และขอบเขตการทดลอง](https://arxiv.org/abs/2312.01037)

ผลดังกล่าวไม่ได้พิสูจน์ว่าโมเดลทุกตัว “รู้คำตอบแต่แกล้งไม่บอก” หรือว่าแค่เปลี่ยน prompt จะดึงความรู้ทุกเรื่องออกมาได้ การวัด probe เองต้องแยกชุดฝึกกับชุดทดสอบด้วย

## ตัวอย่างการทดสอบที่ทำเองได้

เลือกคำถามเชิงตรรกะที่มีเฉลยตรวจได้ แล้วสร้าง prompt สี่แบบ:

| แบบ | เปลี่ยนอะไร | ต้องระวังอะไร |
|---|---|---|
| A | ถามตรง ๆ | เป็น baseline |
| B | เปลี่ยนคำแต่คงข้อมูล | ทดสอบความไวต่อถ้อยคำ |
| C | ให้โครงวิธีคิด แต่ไม่ให้คำตอบ | ทดสอบผลของ scaffolding |
| D | เพิ่มข้อเท็จจริงที่เดิมไม่มี | แยกผลของข้อมูลใหม่ |

หาก C ดีกว่า A อาจแปลว่าการจัดขั้นตอนช่วย หาก D ดีกว่า A อาจเพียงเพราะข้อมูลครบขึ้น ถ้า B เปลี่ยนคำแล้วคะแนนแกว่งมาก ระบบยังไม่ stable ตามความหมายในภาพ

## ใช้กับการเรียนและออกแบบเครื่องมืออย่างไร

ก่อนเพิ่มโมเดลใหญ่ขึ้น ลองตรวจว่าข้อมูลที่จำเป็นอยู่ใน prompt หรือ retrieval แล้วหรือยัง คำศัพท์มีความหมายตรงกันหรือไม่ และรูปแบบคำตอบเหมาะกับงานหรือไม่ หากคำถามต้องคำนวณแน่นอน ให้ใช้ตัวคำนวณหรือ verifier ช่วยยืนยันผล

ข้อเสนอสำหรับบันทึกการทดลอง: เก็บคำถามต้นฉบับ สิ่งที่เปลี่ยนใน prompt คำตอบ และเหตุผลที่ตัดสินว่าถูก การเก็บเฉพาะบทสนทนาที่สำเร็จจะทำให้ดูเหมือนภูมิประเทศเดินง่ายกว่าความจริง

**คำถามทบทวน:** เมื่อให้คำใบ้แล้วโมเดลตอบถูก เราพิสูจน์อะไรแล้วบ้าง? พิสูจน์เพียงว่าคำใบ้ช่วยในกรณีนั้น ยังต้องทดลองเพิ่มจึงแยกได้ว่าช่วยเข้าถึงข้อมูลเดิมหรือเพิ่มข้อมูลที่ขาด

## ตรวจสอบและค้นคว้าเพิ่มเติม — รอบ 2

ตรวจวันที่ 2026-09-20 · อ่านแหล่งต้นทางเพิ่มและเทียบกับคำอธิบายเดิม

### งานวิจัยเพิ่ม: probe อ่านความรู้หรือเรียนงานใหม่เอง

**Designing and Interpreting Probes with Control Tasks — Hewitt และ Liang, EMNLP 2019** เสนอ control task ที่จับคู่ชนิดคำกับป้ายสุ่ม เพื่อประเมินว่าความสำเร็จของ probe มาจาก representation หรือความสามารถจดจำของตัว probe เอง งานทดลองกับงานภาษาและ ELMo พบว่า accuracy สูงอย่างเดียวอาจทำให้ตีความข้อมูลภายในเกินหลักฐาน [บทคัดย่อและ paper](https://aclanthology.org/D19-1275/)

**Eliciting Latent Predictions from Transformers with the Tuned Lens — Belrose และคณะ, preprint 2023** ฝึก affine probe ของแต่ละ block บนโมเดลที่ตรึงไว้ เพื่อแปลง hidden state เป็นการกระจาย token และติดตามว่าคำทำนายเปลี่ยนผ่าน layer อย่างไร งานเปรียบเทียบกับ logit lens และทำ causal experiments เพิ่มเติม ผลสนับสนุนประโยชน์ของเครื่องมือในโมเดลที่ทดสอบ แต่ probe ไม่ใช่คำอธิบายทุกขั้นความคิดของโมเดล [paper ต้นทาง](https://arxiv.org/abs/2303.08112)

### เพิ่มวิธีตรวจภาพ “พื้นที่ความรู้”

ถ้าฝึก classifier ขนาดใหญ่ให้อ่าน hidden state แล้วตอบโจทย์ได้ เราต้องถามว่าตัว classifier เรียนขั้นตอนแก้โจทย์เองหรือไม่ การเริ่มจาก probe ง่าย ๆ เปรียบเทียบกับข้อมูลสุ่มหรือ control task และแยกชุดทดสอบ ช่วยให้คำอ้างว่า “ข้อมูลอยู่ใน representation” มีขอบเขตชัดขึ้น

อย่างไรก็ดี ข้อมูลที่อ่านออกไม่ได้แปลว่าโมเดลเดิมใช้ข้อมูลนั้นจริงขณะตอบ การแทรกแซง เช่น ตัดหรือเปลี่ยนทิศทางที่สงสัยแล้ววัดพฤติกรรม เป็นคำถามเพิ่มอีกระดับ การตีความควรแยก **decode ได้**, **มีผลเชิงเหตุและผล**, และ **ใช้ประโยชน์ได้อย่างทนทาน**

### ตัวอย่างออกแบบเอง

ให้ policy มี hidden vector ของ NPC แล้วใช้ linear probe ทำนายว่า “มีทางหนีหรือไม่” เปรียบเทียบกับ probe ที่เห็นเพียง NPC ID และกับ control label ที่สุ่มผูกกับแต่ละ ID หาก probe แบบ ID ได้คะแนนดีมาก แสดงว่าชุดข้อมูลอาจเปิดทางให้จำตัวละคร แทนที่จะอ่านสถานการณ์

แยกแผนที่และตัวละครบางส่วนไว้ทดสอบ แล้วเปลี่ยนตำแหน่งประตูโดยคง ID เดิม จากนั้นตรวจว่าคะแนน probe และ action ของ policy เปลี่ยนสอดคล้องกับทางหนีจริงหรือไม่ นี่เป็นข้อเสนอประยุกต์หลักการ control task ไม่ใช่การทำซ้ำการทดลองภาษาของ paper โดยตรง

**ผลการตรวจ:** บทเดิมแยก internal representation กับ output ถูกแล้ว งานเพิ่มชี้ว่าการกล่าวว่า “มีความรู้ซ่อนอยู่” ต้องควบคุมความสามารถของเครื่องมือที่ใช้ดึงข้อมูลออกมาด้วย และภาพฉายสองมิติไม่ทดแทนการตรวจเหล่านี้
