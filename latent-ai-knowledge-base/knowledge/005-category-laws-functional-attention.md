## สิ่งที่อยู่ในโพสต์มีสองส่วน

ภาพเป็นตาราง “Category Theory for Tiny ML in Rust” กล่าวถึง functor, natural transformation, monoid และ chain rule ขณะที่ลิงก์เปิดไปยัง paper ชื่อ Functional Attention: From Pairwise Affinities to Functional Correspondences จึงควรเรียนสองประเด็นที่เชื่อมกันได้ โดยไม่อ้างว่าตารางในภาพเป็นเนื้อหาตรงจาก paper

แก่นของตารางคือเปลี่ยนคำคณิตศาสตร์นามธรรมให้เป็นคุณสมบัติที่ตรวจได้ว่าโปรแกรมยังรักษาไว้หรือไม่

## กฎในภาพหมายถึงอะไร

| แนวคิด | สิ่งที่ต้องรักษา | ตัวอย่างเพื่อความเข้าใจ |
|---|---|---|
| Functor | identity และ composition | map ฟังก์ชันเอกลักษณ์แล้วข้อมูลเดิม; map f แล้ว g เทียบกับ map g∘f |
| Natural transformation | แปลงโครงสร้างกับ map สลับลำดับกันได้ตามกฎ | เลือกสมาชิกแรกเป็น Option แล้ว map เทียบกับ map ทั้งรายการแล้วเลือกตัวแรก; รายการว่างให้ None |
| Monoid | identity และ associativity | ต่อบันทึกเหตุการณ์กับรายการว่างแล้วไม่เปลี่ยน; จัดวงเล็บใหม่ได้โดยลำดับเดิม |
| Chain rule | อนุพันธ์ของฟังก์ชันประกอบคูณตามเส้นทาง | gradient จากชั้นถัดไปต้องคูณอนุพันธ์เฉพาะจุด |

คำอธิบายสามแถวแรกสอดคล้องกับกรอบใน [ตำรา Category Theory for Scientists ของ MIT](https://ocw.mit.edu/courses/18-s996-category-theory-for-scientists-spring-2013/9cf51d1394fc107baa6764d553dd0bb6_MIT18_S996S13_textbook.pdf) ตัวอย่างข้างต้นสร้างขึ้นเพื่อให้ลองคำนวณได้เอง ไม่ใช่ผลทดลองใน paper

## ตัวอย่างกฎที่ใช้ตรวจความคิดได้

ให้รายการเป็น [2, 3], f(x)=x+1 และ g(x)=2x:

~~~text
map f แล้ว map g: [2, 3] → [3, 4] → [6, 8]
map (g∘f) ครั้งเดียว: [2, 3] → [6, 8]
~~~

การรวมสองรอบเป็นรอบเดียวควรรักษาผลลัพธ์เมื่อฟังก์ชันบริสุทธิ์ แต่ Rust Iterator รับ closure ที่มี state ได้ด้วย กฎคณิตศาสตร์จึงไม่ใช่ข้อรับรองอัตโนมัติของ closure ทุกตัว [Rust Iterator::map](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.map)

สำหรับ chain rule ให้ y=(2x+1)² ที่ x=1 จะได้ dy/dx = 2(2x+1)×2 = 12 หากระบบ autodiff คืน 6 แสดงว่าลืมคูณอนุพันธ์ของขั้น x→2x+1 นี่เป็นตัวอย่างตรวจการส่ง gradient ที่เล็กพอจะคิดด้วยมือ

## Functional Attention เสริมอะไร

งานที่ลิงก์ไว้เปลี่ยนมุมมองจาก attention จับคู่ token ไปสู่การแปลงระหว่างฐานแทนฟังก์ชัน ใช้ตัวดำเนินการเชิงเส้นแบบมีโครงสร้างเพื่อจับความสัมพันธ์ระดับสนามข้อมูล ทดลองกับ operator learning เช่น PDE และข้อมูลสามมิติ [paper ต้นฉบับ](https://arxiv.org/html/2605.31559v1)

อุปมาเพื่อเรียนรู้: แทนที่จะบอกว่าทุกจุดของแผนที่สัมพันธ์กับทุกจุดอย่างไร เราอาจแทนสนามด้วยส่วนประกอบพื้นฐาน แล้วคำนวณว่าส่วนประกอบเหล่านั้นแปลงถึงกันอย่างไร รายละเอียดและต้นทุนขึ้นกับจำนวนฐานและรูปแบบข้อมูล จึงยังสรุปไม่ได้ว่า attention ทุกแบบจะกลายเป็น O(N) หรือแทน LLM เดิมได้โดยตรง

## นำไปใช้ต่อ

เมื่อสร้าง pipeline ให้เขียน “กฎที่ต้องรักษา” ข้างการแปลงทุกจุด เช่น เปลี่ยน layout แล้วลำดับเหตุการณ์ต้องเดิม หรือเปลี่ยน representation แล้ว action ที่ถูกกฎหมายต้องเดิม จากนั้นเลือกตัวอย่างที่ทำให้กฎผิดได้ง่าย เช่น ข้อมูลว่าง ขนาดไม่เท่ากัน และค่าขอบเขต

**คำถามทบทวน:** การบวก floating point จัดวงเล็บใหม่แล้วได้ bit เหมือนเดิมทุกครั้งหรือไม่? ไม่เสมอ ดังนั้นกฎ associativity ที่จริงในจำนวนจริงต้องนำมาใช้กับฮาร์ดแวร์โดยกำหนด tolerance หรือวิธีคำนวณให้ชัด

## ตรวจสอบและค้นคว้าเพิ่มเติม — รอบ 2

ตรวจวันที่ 2026-09-20 · อ่านแหล่งต้นทางเพิ่มและเทียบกับคำอธิบายเดิม

### งานวิจัยเพิ่ม: การประกอบส่วนเรียนรู้มีเงื่อนไขทางคณิตศาสตร์

**Backprop as Functor: A Compositional Perspective on Supervised Learning — Fong, Spivak และ Tuyéras, preprint 2017; ฉบับอ่าน v3 ปี 2019** นิยาม learning component ที่มีพารามิเตอร์ การทำนาย กฎอัปเดต และข้อมูลส่งกลับไปยังส่วนก่อนหน้า ผู้วิจัยพิสูจน์ความสอดคล้องของการประกอบกับ gradient descent ในกรอบที่กำหนด step size และเงื่อนไขของ loss ไว้ชัดเจน จึงเชื่อม category theory กับการเรียนรู้ได้มากกว่าการเปรียบเปรย [Theorem III.2 และสมมติฐาน](https://arxiv.org/pdf/1711.10455)

ผลเป็นทฤษฎีของโครงสร้างการประกอบ ไม่ใช่ benchmark ว่าใช้ศัพท์ functor แล้วโมเดลเล็กลงหรือรันเร็วขึ้น และไม่ได้บอกว่า optimizer ที่มี state ทุกชนิดจะเข้าทฤษฎีเดียวกันโดยไม่ปรับนิยาม

### แก้รายละเอียดตัวอย่างให้ครบชนิดข้อมูล

การ “เลือกสมาชิกแรก” จากรายการว่างไม่มีคำตอบ ถ้าจะใช้เป็นตัวอย่าง natural transformation ให้กำหนดผลเป็น Option: `head([])=None` และ `head([a,...])=Some(a)` กฎที่อยากรักษาคือ `head(map(f,xs)) = map_Option(f,head(xs))` ทั้งรายการว่างและไม่ว่าง นี่ทำให้กฎมีความหมายกับทุก input ในโดเมนที่ประกาศไว้ ไม่ซ่อนกรณีขอบเขต

อีกความต่างที่ควรจำคือ **associativity ไม่ใช่ commutativity** การต่อ event log แบบ `(A+B)+C = A+(B+C)` ไม่ได้อนุญาตให้เปลี่ยนเป็น `B+A+C` เช่น “รับเงินแล้วซื้อของ” กับ “ซื้อของแล้วรับเงิน” อาจมีผลต่างกัน การ parallelize จึงต้องรักษาลำดับเหตุการณ์ที่มีผลต่อ state ด้วย

### ใช้ตรวจ pipeline อย่างเป็นขั้นตอน

ตัวอย่างออกแบบเอง ให้ encoder E ย่อสถานะเกม, U อัปเดตสถานะจริง และ V อัปเดตใน latent สิ่งที่ต้องถามคือ E(U(x,a)) ใกล้กับ V(E(x),a) เพียงใด สำหรับ action เดียวกัน หากไม่สอดคล้อง การวางแผนใน latent จะค่อย ๆ หลุดจากโลกแม้การคูณเมทริกซ์ทุกครั้งจะถูกชนิดข้อมูล

ทดลองประตูเปิด/ปิดเป็นตัวแปรสำคัญ: ย่อสถานะก่อนแล้วอัปเดต กับอัปเดตจริงก่อนแล้วย่อ ต้องให้ผลต่อ action ที่ทำได้สอดคล้องกัน ระบุ tolerance สำหรับค่าต่อเนื่อง และใช้ความเท่ากันแบบ exact สำหรับสิทธิ์ผ่านประตู ตัวอย่างนี้เป็นเกณฑ์ออกแบบ ไม่ใช่ theorem ใหม่ที่อนุมานจากรูปในโพสต์

**ผลการตรวจ:** รูป category laws กับ paper Functional Attention ยังต้องแยกแหล่งอ้างอิงตามเดิม ส่วนที่เพิ่มทำให้เห็นประโยชน์ของกฎในฐานะสัญญาระหว่างส่วนประกอบ โดยต้องระบุโดเมน ชนิดข้อมูล และเงื่อนไขของกฎให้ครบ
