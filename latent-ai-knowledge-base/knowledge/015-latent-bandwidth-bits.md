# 015 — 40,960 บิตกับ 15 บิต: อ่านตัวเลข Latent Reasoning ให้ถูกความหมาย

## โพสต์และภาพบอกอะไร

โพสต์ชี้ช่องว่างระหว่างการส่งข้อมูลด้วย token กับ hidden state ภาพเทียบ explicit reasoning ที่ส่ง token ไปทีละขั้น กับ latent reasoning ที่ส่งเวกเตอร์เต็มและอาจวนได้ทั้งตามขั้นเวลาและความลึกของโมเดล

คำอธิบายใต้ภาพระบุ hidden state 2,560 มิติแบบ FP16 และประมาณ token หนึ่งตัวไว้ที่ 15 บิต ตัวเลขจึงเป็นการเปรียบเทียบรูปแบบการแทนข้อมูลในตัวอย่างที่เลือก ไม่ใช่ผลวัดความฉลาด

## ลองคำนวณเอง

FP16 ใช้พื้นที่ 16 บิตต่อหนึ่งค่า ดังนั้น:

~~~text
2,560 ค่า × 16 บิต = 40,960 บิต = 5,120 ไบต์ = 5 KiB
~~~

ถ้ามี vocabulary 32,768 ตัว การเลือกหนึ่ง token จากชุดนั้นต้องใช้รหัสอย่างน้อย log₂(32,768) = 15 บิตในแบบจำลองการเข้ารหัสความยาวคงที่ที่อุดมคติ จึงได้อัตราส่วน 40,960/15 ≈ 2,731

หาก vocabulary เปลี่ยนเป็น 131,072 ตัว ค่านี้จะเป็น 17 บิต อัตราส่วนจึงไม่ใช่ค่าคงที่ของทุกโมเดล ขนาด token ID ที่ implementation เก็บในหน่วยความจำจริง เช่น 32 บิต ก็เป็นอีกเรื่องหนึ่ง

## เหตุใดความจุไม่เท่ากับข้อมูลที่ใช้ประโยชน์ได้

เวกเตอร์ที่มีพื้นที่มากอาจเก็บค่าที่สัมพันธ์กัน ซ้ำกัน หรือมี noise จึงไม่ได้มีสารสนเทศอิสระครบทุกบิต ขณะเดียวกัน token ต้องตีความร่วมกับบริบทก่อนหน้า คำสั้นคำเดียวจึงอาจชี้ความหมายจำนวนมากที่มีอยู่ใน context แล้ว

อีกจุดที่ภาพย่อไว้คือ LLM ที่เขียน CoT ก็มี hidden states ภายในโมเดลอยู่แล้ว และอาจเก็บข้อมูลใน KV cache การบอกว่าระบบนั้น “มีความคิดได้เพียง 15 บิตทั้งหมด” จึงขยายความเกินสิ่งที่ภาพกำลังเปรียบเทียบ

Survey ใช้การเปรียบเทียบนี้เป็นแรงจูงใจในการศึกษาการคิดโดยไม่แปลงทุกขั้นเป็นคำ พร้อมจัดหมวดวิธี latent reasoning หลายแบบ ไม่ใช่สูตรรับประกันความแม่นยำหรือ speedup ตามอัตราส่วนบิต [ฉบับ HTML](https://arxiv.org/html/2507.06203v1)

## ผลต่อการออกแบบระบบ

ตัวอย่างประยุกต์: ถ้าสองโมดูลในเกมใช้ schema ของ state vector เดียวกัน การส่งเวกเตอร์อาจตัดขั้นแปลงเป็นภาษาแล้วอ่านกลับได้ แต่ต้องตกลงตำแหน่งของแต่ละค่า หน่วย ช่วงค่า และ version ให้ตรงกัน เวกเตอร์ต่างโมเดลไม่ได้มีความหมายเข้ากันเพียงเพราะยาวเท่ากัน

ถ้าต้องตรวจสอบเหตุผลโดยคน อาจเก็บ decision trace ที่ระบุ input, constraint และ action ไว้ต่างหาก แทนการถือว่า hidden vector เป็นคำอธิบายที่มนุษย์อ่านได้

## แบบฝึกหัด

คำนวณพื้นที่ของเวกเตอร์ 768 มิติแบบ FP32 แล้วเทียบกับ 2,560 มิติ FP16 จากนั้นถามว่าต้องเพิ่มข้อมูลใดจึงจะเปรียบเทียบคุณภาพได้ คำตอบเรื่องพื้นที่คือ 3,072 ไบต์ แต่ความแม่นยำยังต้องใช้โจทย์และการทดลอง

**สิ่งที่ควรจำ:** บิตบอกขนาดการแทนข้อมูล ส่วนความแม่นยำ ความเร็ว และความสามารถถ่ายโอนความรู้เป็นตัววัดคนละด้าน

## ตรวจสอบและค้นคว้าเพิ่มเติม — รอบ 2

ตรวจวันที่ 2026-09-20 · อ่านแหล่งต้นทางเพิ่มและเทียบกับคำอธิบายเดิม

### งานวิจัยเพิ่ม: ความจุของช่องส่งกับข้อมูลที่เกี่ยวกับงาน

**The Information Bottleneck Method — Tishby, Pereira และ Bialek, arXiv 2000** เสนอกรอบย่อ X เป็นตัวแทน Z โดยรักษาข้อมูลที่ใช้ทำนายตัวแปรเป้าหมาย Y ให้ได้มากภายใต้การบีบอัด คำว่า “ข้อมูลสำคัญ” จึงต้องสัมพันธ์กับสิ่งที่จะทำนาย กรอบเป็นปัญหาการหาค่าที่เหมาะสมและมีสมมติฐานเรื่องการกระจายข้อมูล ไม่ใช่การรับรองว่า hidden state ของโมเดลใดเป็นตัวแทนที่ดีที่สุดแล้ว [paper ต้นฉบับ](https://arxiv.org/pdf/physics/0004057)

สำหรับตัวแปรไม่ต่อเนื่อง กรอบคิดเขียนอย่างย่อได้เป็นการลด I(X;Z) ขณะรักษา I(Z;Y) โดย I คือ mutual information การเอาสมการนี้ไปใช้กับเวกเตอร์จริงต้องเลือกวิธีประมาณข้อมูลและ objective ให้ชัด ไม่สามารถแทน I ด้วยจำนวนไบต์ในไฟล์ตรง ๆ

### ตัวอย่างใหม่: เวกเตอร์ใหญ่ที่มีความไม่แน่นอนเพียงหนึ่งบิต

ให้ B เป็นบิตสุ่ม 0/1 อย่างละครึ่ง แล้วสร้างเวกเตอร์ FP16 ยาว 2,560 ช่องโดยใส่ B ซ้ำทุกช่อง ไฟล์ดิบใช้ 40,960 บิตเหมือนตัวเลขในโพสต์ แต่ทั้งเวกเตอร์มีได้เพียงสองสถานะ ความไม่แน่นอนจึงมีเพียงหนึ่งบิตในตัวอย่างนี้

นี่ไม่ได้กล่าวว่า hidden state ของโมเดลจริงมีแค่หนึ่งบิต แต่แสดงทางคณิตศาสตร์ว่าการคูณ dimension ด้วยจำนวนบิตต่อค่าให้ **ขนาดการแทนข้อมูล** ไม่ใช่จำนวนข้อมูลอิสระที่เกี่ยวข้องกับงานโดยอัตโนมัติ

ในทางกลับกัน ถ้า Y คือ “ประตูเปิดหรือปิด” representation ที่เก็บบิตสถานะประตูถูกต้องหนึ่งบิตอาจเพียงพอต่องานนั้น แต่ถ้า Y เปลี่ยนเป็นการสร้างภาพประตูพร้อมสีและรอยพื้นผิว ข้อมูลหนึ่งบิตย่อมไม่พอ ความต้องการของ downstream task เป็นตัวกำหนดว่าจะยอมสูญเสียอะไรได้

### เปลี่ยนจากแข่งขนาดเวกเตอร์เป็นวัด trade-off

ข้อเสนอทดลอง: ใช้ encoder เดียวกันหลายขนาด เช่น 8, 32 และ 128 มิติ แล้วประเมินโจทย์เดียวกัน แยกตารางเป็นพื้นที่เก็บ, เวลาที่ใช้, ความแม่น และความผิดพลาดในกรณีหายาก ทำการเปรียบเทียบ precision FP32/FP16 แยกอีกแกนเพื่อไม่ให้สาเหตุปะปน

ถ้าเวกเตอร์เล็กลงแต่ยังเลือก action ถูก นั่นเป็นหลักฐานการย่อสำหรับงานนั้น หากข้อมูลย่อยสูญหายจนใช้กับโจทย์ใหม่ไม่ได้ ต้องบันทึกขอบเขตนี้ด้วย การลดข้อมูลไม่ใช่ประโยชน์ที่ไร้ต้นทุน และการเพิ่มข้อมูลก็ไม่ได้มีประโยชน์เสมอ

**ผลการตรวจ:** การคำนวณ 2,560×16 ในบทเดิมถูกต้อง ส่วนอัตราส่วนกับ token เป็นเพียง proxy ของรูปแบบการส่งข้อมูล งานเสริมให้ภาษาที่แม่นขึ้นในการถามว่าช่องส่งที่ใหญ่กว่านำข้อมูลเกี่ยวกับงานมาเพิ่มจริงหรือไม่
