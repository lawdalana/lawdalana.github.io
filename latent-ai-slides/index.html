CHAPTER 01

Representation ไม่ใช่แค่ย่อให้เล็ก

คำถามหลัก

ถ้า encoder เปลี่ยน observation เป็น latent z แล้ว policy ใช้ z เลือก action เราต้องรู้ว่า z ยังเก็บความต่างที่ส่งผลต่อ reward และอนาคตพอหรือไม่

z_t = f_theta(x_t) a_t ~ pi( . | z_t)

reconstruction ดีไม่ได้แปลว่า decision ดี ถ้า feature ที่จำเป็นต่อ action ถูกทิ้งไป

TASK ALIASING

ภาพเหมือนกัน แต่อดีตคนละทาง อนาคตจึงต่าง

ตัวอย่างอ่านเอง

  • ถ้า x_t เป็นภาพเดียว วัตถุตำแหน่งเดียวกันอาจกำลังเคลื่อนคนละทิศ
  • ถ้า z รวมสอง state นี้เป็นจุดเดียว policy จะเห็น action space เดียวกัน แม้ action ที่ดีต่างกัน
  • แก้ด้วยประวัติ, velocity, belief state หรือ representation ที่รักษา transition/reward ที่จำเป็น

บทเรียน: latent ที่ดีเป็น contract กับงาน ไม่ใช่แค่ compression ratio

CHAPTER 02

Attention คือ tensor contract ก่อนเป็นคำอธิบาย

แยกสิ่งที่คงที่กับสิ่งที่เกิดตอนรัน

H คือ activation จาก input ปัจจุบัน ส่วน W_Q, W_K, W_V คือ weights ที่เรียนมาแล้ว Q/K/V จึงเป็นค่าระหว่าง inference ไม่ใช่ความจริงของโลกโดยตรง

Q = H W_Q, K = H W_K, V = H W_V A = softmax(QK^T / sqrt(d_k) + M)

CHAPTER 03

test-time compute ซื้อ “เวลาคิด” ได้หลายแบบ

สามคำถามก่อนเชื่อว่า reasoning ดีขึ้น

  • เพิ่มรอบ recurrence, เพิ่ม branch search หรือปรับ latent ด้วย gradient?
  • จุดหยุดคือ fixed K, confidence, verifier pass หรือ budget หมด?
  • ประโยชน์วัดด้วย accuracy, abstention, latency, หรือ useful throughput?
h_{k+1} = F_theta(h_k, z) p(y|x) = softmax(g_theta(h_K))

CHAPTER 04

คำตอบที่ดีต้องผ่าน specification ไม่ใช่แค่คะแนนสูง

pipeline ที่อ่านง่าย

  • proposer สร้าง action หรือคำตอบที่เป็น candidate
  • constraint จำกัด domain ของตัวเลือก เช่น schema, grammar, mask
  • verifier ตรวจ preconditions, invariants, state version แล้วค่อย commit
accept(a,s) = schema_ok(a) AND preconditions(a,s)

CHAPTER 06

retrieval เลือกหลักฐานก่อน generation

ข้อเท็จจริงที่ deck เน้น

  • similarity ไม่ใช่ entailment: เอกสารใกล้ query อาจผิด version หรือผิด domain
  • context ต้องพก provenance: document id, revision, chunk position, access boundary
  • embedding ไม่ใช่ encryption: vector อาจเผย topic, intent หรือ attribute ได้
sim(q,d) = φ(q)^T φ(d) / (||φ(q)|| ||φ(d)||)

RAG / CODE HEALING

ระบบซ่อมโค้ดที่ดีมี validator หลายชั้น

  • static rule จับ pattern ที่รู้จัก เช่น lint หรือ diagnostics
  • retrieval หา example หรือ rule ใกล้เคียงจาก corpus เฉพาะ domain
  • AST / compiler / tests ตรวจ patch ก่อนเสนอ diff
  • audit log เก็บ missed case กลับ corpus พร้อม false positive/negative

CHAPTER 07

หลาย agent ไม่ใช่ agent เดียวคูณ N

สิ่งที่ต้องเพิ่มในสมมติฐาน

  • agent แต่ละตัวมี observation, memory และสิทธิ์เข้าถึงข้อมูลไม่เท่ากัน
  • policy ของตัวอื่นเปลี่ยน distribution ที่เราเจอ แม้ θ ของตัวเองคงที่
  • coordination อาจใช้ signal ร่วม, mean-field, cache หรือ hierarchy แต่ต้องวัดคุณภาพที่เสียไป

CHAPTER 09

GPU คุ้มเมื่อ overhead ถูกกลืนด้วยงานพอใหญ่

แบบจำลองง่าย: CPU ใช้ N/q_C ส่วน GPU ใช้ τ + N/q_G ถ้า q_G สูงกว่าแต่มี fixed overhead τ จุดตัด N* คือจำนวนงานที่ GPU เริ่มคุ้ม

T_CPU = N / q_C T_GPU = τ + N / q_G N* = τ / (1/q_C - 1/q_G)

ตัวเลขใน source เป็นตัวอย่างสอน ไม่ใช่ threshold ของ hardware ทุกเครื่อง

ตัวอย่าง Amdahl
