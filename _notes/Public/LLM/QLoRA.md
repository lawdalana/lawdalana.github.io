## [QLORA: Efficient Finetuning of Quantized LLMs](https://arxiv.org/pdf/2305.14314)

- การปรับแต่งโมเดลขนาดใหญ่ใช้ทรัพยากรมาก โดยเฉพาะหน่วยความจำ GPU
- การปรับแต่ง LLaMA ขนาด 65B พารามิเตอร์ด้วยความแม่นยำ 16-bit แบบทั่วไปต้องใช้หน่วยความจำ GPU มากกว่า 780 GB
- เทคนิค quantization ที่มีอยู่ช่วยลดหน่วยความจำของ LLM ได้ แต่หลายวิธีรองรับเฉพาะ inference และยังใช้ระหว่างฝึกโมเดลไม่ได้

![Parameter-Efficient Fine-Tuning](/assets/img/Other/LLM/applsci-15-03087-g001.avif)

## 3 Innovation of QLoRA:

**1. 4-bit NormalFloat (NF4)**

**2. Double Quantization (DQ)**

**3. Paged Optimizers**


### 1. 4-bit NormalFloat (NF4): เป็นประเภทข้อมูลใหม่ที่เหมาะสมที่สุดตามทฤษฎีข้อมูล (information theoretically optimal) สำหรับน้ำหนักที่กระจายตัวแบบปกติ
NF4 ให้ผลการทดลองดีกว่า 4-bit Integer และ 4-bit Float อีกทั้งแทนค่าศูนย์ได้ตรง จึงควอนไทซ์น้ำหนักที่เป็นศูนย์ได้โดยไม่เกิดความคลาดเคลื่อน
   - 8 bit = 1 byte
   - FP16 = floating-point 16 bit

#### ขั้นตอนการแปลง FP16 ให้เป็น NF4
ขั้นตอนการแปลงค่าจาก 16-bit (หรือ BFloat16) เป็น NF4:
การแปลงค่าความแม่นยำสูง เช่น 16-bit float หรือ BFloat16 เป็น NF4 เริ่มจากการปรับสเกล (normalization) แล้วจับคู่กับค่ามาตรฐานของ NF4

1. ค่ามาตรฐานของ NF4 (Predefined NF4 Values): NF4 ประกอบด้วย 16 ค่าที่ไม่ต่อเนื่องกัน ซึ่งถูกคำนวณมาจากการประมาณค่าควอนไทล์ (quantiles) ของการกระจายตัวแบบปกติมาตรฐาน (Standard Normal Distribution N(0, 1)) และถูกปรับขนาดให้อยู่ในช่วง [-1, 1]
ค่ามาตรฐานของ NF4 มีดังนี้:
: [-1.0, -0.6961928009986877, -0.5250730514526367, -0.39491748809814453, -0.28444138169288635, -0.18477343022823334, -0.09105003625154495, 0.0, 0.07958029955625534, 0.16093020141124725, 0.24611230194568634, 0.33791524171829224, 0.44070982933044434, 0.5626170039176941, 0.7229568362236023, 1.0]

NF4 มี 16 ค่า (7 ลบ + 1 ศูนย์ + 8 บวก)

2. การปรับขนาดน้ำหนักโมเดล (Normalization): ก่อนที่จะแมปค่า น้ำหนักของโมเดลที่ต้องการควอนไทซ์ (ซึ่งอาจเป็น 16-bit float หรือ BFloat16) จะถูกนำมาปรับขนาดให้อยู่ในช่วง [-1, 1] โดยการหารค่าแต่ละค่าในบล็อกนั้นด้วยค่าสัมบูรณ์สูงสุด (absolute maximum) ของบล็อกน้ำหนักนั้น
การปรับสเกลช่วยให้ค่าน้ำหนักอยู่ในช่วงที่ใช้ควอนไทซ์

ตัวอย่างการแปลงค่าจาก 16-bit float เป็น NF4:
สมมติว่าเราต้องการแปลงน้ำหนัก 0.58 ซึ่งเป็นค่า 16-bit float ในบล็อกหนึ่งให้เป็น NF4
- กำหนดค่า 16-bit float ที่จะแปลง: สมมติ W_BF16 = 0.58
- หาค่าสัมบูรณ์สูงสุดของบล็อกน้ำหนัก: สมมติว่า absmax ของบล็อกที่มี W_BF16 คือ 0.8 โดยค่านี้คำนวณจากทั้งบล็อก
- ปรับขนาดค่า W_BF16: นำ W_BF16 มาปรับขนาดให้อยู่ในช่วง [-1, 1] โดยการหารด้วย absmax ของบล็อกนั้น: W_normalized = W_BF16 / absmax = 0.58 / 0.8 = 0.725
- การควอนไทซ์ (Mapping to NF4): เลือกค่าที่ใกล้กับ W_normalized (0.725) ที่สุดจากค่า NF4 ทั้ง 16 ค่า โดยพิจารณาค่าต่อไปนี้:
    - 0.5626170039176941
    - 0.7229568362236023 (ค่านี้อยู่ใกล้ 0.725 มาก)
    - 1.0
- ค่า NF4 ที่ใกล้เคียงที่สุดกับ 0.725 คือ 0.7229568362236023
- ทุก block ใช้ค่ามาตรฐาน NF4 ชุดเดียวกันตามรายการข้างต้น แต่มีค่า absmax ของตนเอง

ดังนั้น น้ำหนัก 0.58 ในรูปแบบ 16-bit float เมื่อปรับสเกลแล้วจะจับคู่กับระดับ 0.7229568362236023 ซึ่งเป็นหนึ่งในค่ามาตรฐาน NF4 ทั้ง 16 ค่า
- การเก็บน้ำหนักด้วยวิธีนี้ช่วยลดหน่วยความจำ โดยยังรักษาคุณภาพของโมเดลได้ดี

### 2. Double Quantization (DQ): เป็นวิธีการ Quantize ค่าคงที่ของการ Quantization เพื่อประหยัดหน่วยความจำเพิ่มเติม
DQ ลดหน่วยความจำเฉลี่ยได้ประมาณ 0.37 bits ต่อพารามิเตอร์ หรือประมาณ 3 GB สำหรับโมเดล 65B

```
น้ำหนัก W ─┐
           │  [NF4 4-บิต]          (บล็อก 64)
           ├─► q (4b)
           │   c₂ (FP32) ──┐
           │               ├─► q₂ (FP8)      (บล็อก 256)
           │               └─► c₁ (FP32)
           └─► จัดเก็บ {q, q₂, c₁}
```

### Result (Memory & Accuracy)
**Memory** การประหยัดหน่วยความจำ


    Memorybase = weights 0.5 B/param + DQ constants (0.127 bits/param ÷ 8 bits/byte)
               ≈ 0.516 B/param

    เทียบกับ 16-บิต (2.0 B/param) ⇒ เล็กลง ≈ 3.9×
    LLaMA-65B: 33 GB (4-bit+DQ) vs 130 GB (fp16)
    arXiv


**Accuracy**
```
| Benchmark           | 16-bit LoRA | 4-bit NF4 | 4-bit NF4 + DQ |
| ------------------- | ----------- | --------- | -------------- |
| MMLU 7-65B (5-shot) | 53.0        | 52.2      | **53.1**       |
```

### 3. Paged Optimizers: เพื่อแก้ไขปัญหาการใช้หน่วยความจำที่พุ่งสูงขึ้น (memory spikes) ระหว่างการ Fine-tuning โมเดลภาษาขนาดใหญ่
Paged Optimizers ใช้ Unified Memory ของ NVIDIA เพื่อย้ายข้อมูลระหว่างหน่วยความจำ CPU และ GPU ครั้งละ page เมื่อ GPU มีหน่วยความจำไม่พอ กลไกนี้คล้ายการจัดการหน่วยความจำเสมือนที่ย้ายข้อมูลระหว่าง RAM กับดิสก์

เมื่อหน่วยความจำ GPU เริ่มไม่พอ ระบบจะย้ายสถานะของ optimizer ไปพักใน RAM ของ CPU และโหลดกลับมายัง GPU เมื่อต้องใช้ในขั้นอัปเดตโมเดล

วิธีนี้ช่วยลดปัญหา out-of-memory ระหว่าง fine-tuning โมเดลขนาดใหญ่บน GPU ตัวเดียว เช่น โมเดล 33B หรือ 65B พารามิเตอร์บน GPU ขนาด 24GB หรือ 48GB

## Summary

![Parameter-Efficient Fine-Tuning](/assets/img/Other/LLM/qlora_001.avif)

- QLoRA ลดการใช้หน่วยความจำจนปรับแต่งโมเดลขนาด 65B พารามิเตอร์บน GPU ขนาด 48GB เพียงตัวเดียวได้ โดยผลทดลองมีคุณภาพใกล้เคียงการปรับแต่งแบบ 16-bit
- QLoRA ส่ง gradient ย้อนผ่านโมเดลฐานที่ควอนไทซ์เป็น 4-bit และตรึงน้ำหนักไว้ (frozen) เพื่ออัปเดต Low-Rank Adapters (LoRA)
- เริ่มจากควอนไทซ์โมเดลที่ผ่าน pretraining เป็น 4-bit แล้วเพิ่มน้ำหนัก LoRA จำนวนเล็กน้อยที่ฝึกเพิ่มเติมได้
- QLoRA เก็บน้ำหนักด้วยชนิดข้อมูลความแม่นยำต่ำ เช่น 4-bit NormalFloat และคำนวณด้วยชนิดข้อมูลความแม่นยำสูงกว่า เช่น BFloat16
  เมื่อใช้น้ำหนัก ระบบจะ dequantize เทนเซอร์เป็น BFloat16 ก่อนคูณเมทริกซ์แบบ 16-bit
- การอัปเดตพารามิเตอร์ใช้ gradient ของน้ำหนัก adapter โดยไม่อัปเดตน้ำหนักฐาน 4-bit
ผลลัพธ์และผลกระทบที่สำคัญ:
- ประสิทธิภาพเทียบเท่า 16-bit: ผลทดลองของ QLoRA แสดงว่าปรับแต่งโมเดลที่ควอนไทซ์เป็น 4-bit ได้โดยคุณภาพไม่ลดลง
  QLoRA 4-bit ที่ใช้ NF4 ให้ผลใกล้เคียง 16-bit full fine-tuning และ 16-bit LoRA fine-tuning บนชุดทดสอบทางวิชาการ
- การเข้าถึงเทคโนโลยี: QLoRA ลดหน่วยความจำเฉลี่ยที่ต้องใช้ปรับแต่งโมเดล 65B พารามิเตอร์จาก >780GB เหลือ <48GB
  ทำให้ทีมที่มี GPU เพียงตัวเดียวปรับแต่งโมเดลขนาดใหญ่ที่เปิดเผยต่อสาธารณะในช่วงที่งานวิจัยเผยแพร่ได้
- โมเดล Guanaco: โมเดลที่ปรับแต่งด้วย QLoRA ทำคะแนน Vicuna benchmark ได้สูงกว่าโมเดลเปิดที่นำมาเปรียบเทียบ
  Guanaco 65B ทำได้ 99.3% ของคะแนน ChatGPT และใช้เวลาปรับแต่ง 24 ชั่วโมงบน GPU ตัวเดียว ส่วน Guanaco 7B ใช้หน่วยความจำ 5 GB และทำคะแนนสูงกว่า Alpaca ที่ใช้ 26 GB มากกว่า 20 เปอร์เซ็นต์
- การศึกษาเชิงลึก: หน่วยความจำที่ลดลงทำให้ศึกษาการปรับแต่งตามคำสั่งและคุณภาพ chatbot ในโมเดลขนาดใหญ่ได้มากขึ้น
  งานนี้ฝึกโมเดลมากกว่า 1,000 โมเดลเพื่อใช้วิเคราะห์
- คุณภาพข้อมูลสำคัญกว่าปริมาณ: ชุดข้อมูล OASST1 ขนาด 9k ตัวอย่างให้คุณภาพ chatbot ดีกว่าชุดข้อมูล FLAN v2 ขนาด 450k ตัวอย่าง
- การประเมิน chatbot: งานวิจัยเปรียบเทียบการประเมินโดยมนุษย์กับ GPT-4 และพบว่า GPT-4 เป็นทางเลือกที่คุ้มค่าสำหรับการประเมินในงานนี้
- การเผยแพร่ผลงาน: ผู้วิจัยเปิดโค้ด โมเดล และ CUDA kernels สำหรับฝึกแบบ 4-bit รวมถึงนำวิธีนี้ไปรวมในระบบ Hugging Face transformers
- ผลต่อทีมขนาดเล็ก: QLoRA ช่วยลดช่องว่างด้านทรัพยากรระหว่างองค์กรใหญ่กับทีมที่ใช้ GPU ระดับผู้บริโภค
  และเป็นแนวทางต่อยอดการปรับแต่ง LLM บนอุปกรณ์ขนาดเล็ก เช่น โทรศัพท์มือถือ รวมถึงงานที่ต้องการเก็บข้อมูลส่วนตัว

## 6. Empirical Results & Benchmarks (2 min)

- **Accuracy retention**  
  - On common NLP benchmarks (e.g., GLUE/SQuAD), QLoRA typically matches FP16+LoRA within ~±0.1–0.5% when adapter ranks and target layers are chosen appropriately.

- **Throughput & GPU-RAM**  
  - ~4× lower GPU memory for base weights, enabling larger batch/sequence or bigger models per GPU.  
  - End-to-end training speedups of roughly 1.2×–1.5× on A100-class hardware, with variance by model size, sequence length, and kernel fusion.

- **การคงความแม่นยำ**  
  - บนชุดทดสอบ NLP ทั่วไป เช่น GLUE/SQuAD มีรายงานว่า QLoRA ให้ผลต่างจาก FP16+LoRA ภายใน ~±0.1–0.5% เมื่อตั้งค่า rank และ target layers อย่างเหมาะสม

- **อัตราประมวลผลและหน่วยความจำ GPU**
  - หน่วยความจำ GPU สำหรับน้ำหนักฐานลดลง ~4× จึงเพิ่มขนาด batch ความยาวลำดับข้อมูล หรือขนาดโมเดลต่อ GPU ได้
  - ความเร็วในการฝึกทั้งกระบวนการเพิ่มขึ้นราว 1.2×–1.5× บนฮาร์ดแวร์ระดับ A100 โดยขึ้นกับขนาดโมเดล ความยาวลำดับข้อมูล และการรวม kernel
